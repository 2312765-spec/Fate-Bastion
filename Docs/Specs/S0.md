**Assembly và hướng phụ thuộc** (khóa sau S0; sửa = PR 3 người duyệt, cập nhật cùng `CLAUDE.md` mục 4):

```
Core ← Combat ← Enemies ← Skills ← Heroes ← Player
Core ← Meta
Game  → Heroes, Enemies, Player, Meta
UI    → Core, Combat, Enemies, Skills, Heroes, Game, Meta
Audio → Core (+ `Unity.Cinemachine` cho rung camera)
Editor → mọi asmdef (chỉ Editor)
```

- Heroes/Skills cần Enemies để chọn mục tiêu theo `distance` trên Spline, boss, quái Bay; Player cần Enemies để Thiên thạch tính máu theo `LevelData`; Game cần Meta để trả Ngọc sau trận.
- UI chỉ **hiển thị** qua event và field ScriptableObject; được gọi hàm lệnh public (`TimeController`, `GachaService`, `CollectionService`, `DeckService`, bán/nâng tướng) khi người chơi bấm nút.
- API cụ thể ở từng điểm nối giữa hai người (quái tới Thành, wave, pool tướng, cấp tướng, Nộ, Esc, Vàng): `Docs/TEAM_ASSIGNMENT.md` mục 3.1. Spec từng hệ thống ghi lại đúng các tên đó.
- Package: Enemies → `Unity.Splines`, `Unity.Mathematics`; Player → `Unity.InputSystem`, `Unity.Cinemachine`; UI → `UnityEngine.UI`, `Unity.TextMeshPro`, `PrimeTween.Runtime`.

**Ánh xạ CSV → asset** (công cụ Tools → Import Balance CSV):

|File|Asset tạo ra|Quy tắc|
|---|---|---|
|heroes.csv|`HeroData` tên `<id>` và `SkillData` tên `<id>_passive`|Cột id … range ghi vào HeroData. areaRadius ghi vào passive.radius; buffType ≠ None thì passive có kind Buff với buffValue, buffRadius. Cột notes và calc_* bỏ qua.|
|enemies.csv|`EnemyData` tên `<id>`|Ghi đủ 10 cột; flying và boss đọc TRUE/FALSE, không phân biệt hoa thường.|
|waves.csv|`WaveData` tên `L<level>_W<wave>`; `LevelData` tên `level_<level>`|Mỗi loại quái có số lượng > 0 thành 1 SpawnGroup, theo thứ tự normal → fast → armored → flying → boss; startDelay = thứ tự group × 2 giây; interval = spawnInterval; flying dùng pathIndex 1, còn lại pathIndex 0; isBossWave = boss > 0. LevelData nhận 15 WaveData theo thứ tự wave.|

Quy tắc chung của công cụ import:

- Hàng 1 là tên cột. Hàng có ô đầu tiên bắt đầu bằng `#` bị bỏ qua (hàng mô tả tiếng Việt). Cột không có trong bảng trên bị bỏ qua.
- Asset đã có cùng tên thì cập nhật, không tạo trùng. Asset có trong project nhưng không có trong CSV thì không xóa, chỉ ghi cảnh báo.
- File CSV lưu dạng **UTF-8 có BOM** (Excel: Save As → "CSV UTF-8"), để Excel mở không lỗi font tiếng Việt. Công cụ import đọc bằng `File.ReadAllText(path, Encoding.UTF8)` và bỏ ký tự BOM ở đầu nếu có.
- Đọc số bằng `CultureInfo.InvariantCulture` (dấu chấm thập phân). Chấp nhận cả dấu phân cách `,` và `;` (xác định từ hàng 1, vì hàng tên cột không có ô nào chứa dấu phân cách), vì Excel trên Windows tiếng Việt có thể lưu CSV bằng `;`. Phải dùng bộ đọc CSV hiểu ô trong ngoặc kép, không dùng `Split(',')`: cột notes có dấu phẩy và chấm phẩy nên được Excel bọc trong `"..."`. Trong Excel nên tắt "Use system separators" (File → Options → Advanced) và đặt dấu thập phân là dấu chấm.
- Giá trị enum sai hoặc số không đọc được: ghi lỗi kèm tên file và số dòng, bỏ qua dòng đó, không dừng cả lần import.
- Tiêu chí hoàn thành S0: unit test bộ đọc CSV với ô có dấu phẩy trong ngoặc kép, file có BOM, file dùng dấu `;`; import 3 file mẫu tạo đúng 9 HeroData, 9 SkillData bị động, 5 EnemyData, 45 WaveData, 3 LevelData; chạy import lần 2 không tạo thêm asset nào.

Cách dùng tab này với Claude Code:

1. Mỗi hệ thống một nhánh `feature/s<số>-<tên>`.
2. Dán phần đặc tả của hệ thống đó vào `Docs/Specs/S<số>.md` trong repo, rồi dùng Prompt gợi ý ở cuối mục.
3. Yêu cầu Claude lập kế hoạch trước (plan mode), duyệt rồi mới cho code.
4. Viết test theo Tiêu chí hoàn thành trước hoặc cùng lúc với code; chạy Unity Test Runner.
5. Mở Pull Request, người khác review và chơi thử trước khi merge.
6. Thay đổi thiết kế trong lúc làm thì cập nhật lại đặc tả này trước.
